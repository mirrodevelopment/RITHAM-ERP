================================================================================
SECTION 1 — WHAT IS RITHAM ERP?
================================================================================

Ritham ERP is a computer software system built specifically for Ritham Garments.
It runs inside a web browser (like Chrome or Edge) on any computer connected to
your local network. It manages everything from taking a customer's order, tracking
that order through every stitching stage, collecting payment, and finally marking
delivery as complete.

Think of it like a digital notebook that every team member can read and update
from their own computer — but with rules about who can change what.

--------------------------------------------------------------------------------
HOW THE SYSTEM RUNS
--------------------------------------------------------------------------------

The system has two main parts working together:

  1. THE BACK-END (The Engine)
     - Built with Java and Spring Boot (a professional server framework)
     - Runs on a server computer at port 8080
       (meaning: you open a browser and go to http://localhost:8080)
     - Stores all data in a PostgreSQL database named "ritham_erp"
     - The database has a user called "ritham" with password "ritham123"
     - All the business rules live here (who can do what, how orders are saved,
       how payments work, etc.)

  2. THE FRONT-END (What You See)
     - Built with plain HTML, CSS, and JavaScript
     - Files are stored in the "frontend" folder
     - Every page is served directly from the back-end server
     - No separate app needs to be installed — just open a browser

  HOW TO START THE SYSTEM:
  - Double-click "start.bat" in the main folder, OR
  - Run the command: mvnw.cmd spring-boot:run
  - Wait about 30 seconds for the server to start
  - Open your browser and go to: http://localhost:8080

SECTION 2 — THE DATABASE (WHERE ALL INFORMATION IS SAVED)
================================================================================

All information is permanently saved in a database. The database is built up
step by step using "migration files" (numbered V1, V2, V3, etc.). Each file
adds new tables or data. Here is what each table stores:

  TABLE: roles
  - The four job roles in the system:
    1. ROLE_ADMIN                → Administrator (full access to everything)
    2. ROLE_OPERATIONS_MANAGER   → Operations Manager (monitoring only, view-only)
    3. ROLE_PRODUCTION_EMPLOYEE  → Production floor worker (assigned to a stage)
    4. ROLE_RECEPTION            → Reception desk (registers customers, creates orders)

  TABLE: departments
  - Four departments: Administration, Production, Operations, Reception

  TABLE: employees
  - Every person who uses the system has a record here
  - Stores: employee code, full name, mobile number, email,
            username (for login), password (encrypted), role, department,
            production stage, and active/inactive status
  - The password is NEVER stored as plain text — it is encrypted using BCrypt
  - The "stage" column tells which production stage a physical staff member works in

  TABLE: customers
  - Every customer who places an order
  - Stores: mobile number (used as the unique ID), customer name, date added
  - The mobile number is the primary way to find a customer

  TABLE: customer_orders
  - Every garment order placed by a customer
  - Stores: order number (like ORD-20260810-0001), customer mobile,
            delivery date, current status (which production stage),
            payment status, total amount, advance paid, amount paid,
            assigned employee ID and name (who is currently working on it)

  TABLE: order_designs
  - Design details attached to an order (design name, notes, images)

  TABLE: order_measurements
  - Body measurements for the garment (stored as JSON text)

  TABLE: order_materials
  - Materials used for the order — either supplied by the company or by the customer

  TABLE: production_tracking
  - A record of every production stage each order passes through
  - Tracks: which stage, which employee handled it, when it started and ended,
            status (Pending / In Progress / Completed)

  TABLE: order_payments
  - Every individual payment received for an order
  - Stores: payment type (Advance or Final), payment method
            (Cash, UPI, Google Pay, Bank Transfer), amount, date

  TABLE: order_deliveries
  - Records when an order was delivered, who delivered it, and whether
    the receipt was printed

  TABLE: refresh_tokens
  - Security records: when a user logs in, the system saves a special
    "refresh token" so they stay logged in for 7 days without re-entering
    their password every 15 minutes

--------------------------------------------------------------------------------
HOW THE DATABASE GROWS (MIGRATION FILES)
--------------------------------------------------------------------------------

The system automatically runs these files in order every time it starts:

  V1  - Creates the roles, departments, employees, and token tables
        Seeds the 4 roles, 4 departments, and creates the admin login
  V2  - Creates customer, order, design, measurement, material, production
        tracking, payment, and delivery tables
  V3  - Added 3 demo customers (for testing)
  V4  - Removed the demo customers
  V5  - Added an "order count" column to customers (tracks how many orders each customer has)
  V6  - Seeded 5 real test customers with sample orders
  V8  - Added "payment mode" column to orders (Cash, UPI, etc.)
  V9  - Added physical staff employee accounts (initial seed)
  V10 - Added "stage" column to employees table
        Deleted old test employees
        Added 16 physical staff employees — 2 for each of the 8 production stages
  V11 - Added "assigned employee" columns to orders (to track who is working on each order)

HOW LOGIN WORKS (THE SECURITY SYSTEM)
--------------------------------------------------------------------------------

1. User opens http://localhost:8080 in the browser
   → They see the Login Page (index.html)

2. User types their username and password and clicks "Sign In"

3. The system sends the username and password to the server
   → Server checks: Is this username correct? Is the password correct?
   → Server checks: Is the account active?

4. If correct, the server sends back two things:
   a) ACCESS TOKEN — a temporary pass, valid for 15 minutes
   b) REFRESH TOKEN — a long-term key, valid for 7 days
   Both are stored in the browser's memory (not on disk for safety)

5. The system also reads the user's ROLE and sends them to the correct dashboard:
   - Admin → Order Desk
   - Reception → Order Desk
   - Operations Manager → Operations Monitoring Desk
   - Production Employee → Production Floor Desk

6. Every 15 minutes, the access token automatically renews using the refresh token
   (the user never needs to log in again as long as they are active)

7. When the user clicks "Logout" → the refresh token is cancelled on the server,
   and the user is sent back to the login page

SECTION 8 — PAYMENT SYSTEM
================================================================================

Payments can be collected at two points:

  1. WHEN ORDER IS CREATED (Advance Payment):
     - Enter advance amount when creating the order
     - Payment status becomes: PARTIAL (if advance < total) or PAID (if full)

  2. AT DELIVERY (Final Payment):
     - Collect remaining balance when customer picks up garment
     - Payment status becomes PAID if fully settled

  PAYMENT METHODS:
  - Cash
  - UPI
  - Google Pay (also treated as UPI)
  - Bank Transfer
  - Card

  PAYMENT STATUS LABELS:
  - PENDING   → "Unpaid"  (no payment received yet)
  - PARTIAL   → "Partial" (advance paid, balance remaining)
  - PAID      → "Paid"    (fully paid)
  - REFUNDED  → "Refunded" (money returned to customer)

  The "Balance Due" is calculated automatically:
  Balance = Total Amount minus Amount Paid

SECTION 9 — PRIORITY SYSTEM

Each order gets a priority level automatically:

  HIGH   → Order total amount is more than Rs.5,000
  NORMAL → Order total amount is Rs.5,000 or less

  This helps production staff focus on high-value orders.

SECTION 10 — SECURITY SYSTEM
================================================================================

  1. ENCRYPTED PASSWORDS
     - No password is ever stored as plain text
     - BCrypt encryption (industry standard) is used
     - Even the database administrator cannot read passwords

  2. JWT TOKENS (Digital Passes)
     - When you log in, you receive a "digital pass" (JWT token)
     - This pass expires in 15 minutes
     - It automatically renews every 15 minutes using a "refresh token"
     - The refresh token lasts 7 days
     - If you log out, the refresh token is cancelled immediately

  3. ROLE-BASED ACCESS CONTROL
     - Every page and every action checks your role first
     - If you try to access a page you're not allowed to → you are redirected to login
     - Examples:
       * Only Admin can add/delete employees
       * Operations Manager sees everything but cannot make changes
       * Production Employee can only see the Production Floor Desk

  4. CORS (Cross-Origin Security)
     - Only connections from approved addresses are allowed
     - The system is set up for local network use

SECTION 13 — WHAT HAPPENS AUTOMATICALLY (NO ACTION NEEDED)
================================================================================

  1. LIVE REFRESH: All dashboards refresh automatically every 10 seconds
     → You don't need to press Refresh manually

  2. TOKEN RENEWAL: Login stays active for 7 days automatically
     → No need to log in every day

  3. ORDER NUMBERS: Generated automatically (ORD-YYYYMMDD-NNNN)
     → No need to manually assign numbers

  4. EMPLOYEE CODES: Generated automatically (EMP-001, EMP-002, etc.)
     → No need to manually assign codes

  5. PAYMENT STATUS: Updates automatically based on amounts
     → PENDING to PARTIAL to PAID is calculated automatically

  6. FOCUS REFRESH: When you switch back to a browser tab, data refreshes
     → Always shows current information

  7. SEARCH DEBOUNCE: Search waits 400ms before sending to server
     → Prevents too many requests while you're still typing

SECTION 14 — TROUBLESHOOTING
================================================================================

  PROBLEM: Cannot open the system / browser shows error
  SOLUTION: Make sure start.bat was run and wait 30 seconds for startup
            Check that no other program is using port 8080

  PROBLEM: Login fails with correct password
  SOLUTION: Check the username is correct (lowercase only)
            Check if the account is set to "Active"
            Contact admin to reset password

  PROBLEM: "Advance" button not working or showing "View Only"
  SOLUTION: You may be logged in as Operations Manager (view-only role)
            Log in with Admin or Production Employee account instead

  PROBLEM: No employees showing in the advance stage popup
  SOLUTION: Check that employees are added and set as "Active" in the
            Employee page for the relevant stage

  PROBLEM: Order not showing on Production Floor Desk
  SOLUTION: Check the order status — if CANCELLED or DELIVERED, it won't show
            Only active (non-cancelled, non-delivered) orders appear

  PROBLEM: Customer not found when creating order
  SOLUTION: The customer must be added first in the Customers page
            Search is exact mobile number match — check for typos
